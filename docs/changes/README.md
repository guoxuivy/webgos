# 一页纸变更记录

本目录用**一页纸**记录会改变外部可观察行为的变更。它比完整需求文档轻，
但足以回答三个问题：**为什么改、改成什么样、改坏了怎么退**。

## 什么时候填

只在这些情况填（判断标准是「外部能否观察到」，不是改动行数）：

- 新接口、新页面、新的可观察行为；
- 修改接口字段、错误语义、权限/鉴权行为；
- 数据库结构变更（**必须**含回滚方案）；
- 纠正一个「现行行为描述本身是错的」的问题。

## 什么时候不填

- 纯重构、等价性能优化、测试补强（需在提交/PR 中说明「行为不变」）；
- 文档、依赖、构建、注释调整。

## 怎么用

1. 复制 [`TEMPLATE.md`](TEMPLATE.md) 到本目录；
2. 文件名：`<yyyy-mm-dd>-<动词>-<能力>.md`，例如 `2026-09-17-add-park-export.md`；
3. 填写，字段保留，不适用的写「不适用：原因」，不要删字段；
4. 与代码**同一个提交/PR**交付。

## 原则

- **一页纸**：写不长说明想不清楚，先去想清楚再动手。
- **验收场景要可执行**：Given / When / Then，能被复现和验证。
- **回滚方案要具体**：写清回退动作，不写「重新发布上一版」这类空话。
